## Теоретическая часть
Параллельные структуры данных требуют синхронизации для избежания состояния гонки (race conditions). В CUDA для этого используются **атомарные операции** (`atomicAdd`, `atomicSub`, `atomicCAS`), которые гарантируют, что только один поток может изменить значение по адресу памяти в данный момент времени.

### Основные структуры
1. **Стек (Stack - LIFO)**:
   - `push`: атомарное увеличение индекса вершины (`top`).
   - `pop`: атомарное уменьшение индекса вершины.
2. **Очередь (Queue - FIFO)**:
   - `enqueue`: атомарное увеличение индекса хвоста (`tail`).
   - `dequeue`: атомарное увеличение индекса головы (`head`).

## Инструкция по запуску
Для компиляции и запуска программ используйте `nvcc` (NVIDIA CUDA Compiler).

### Компиляция
```bash
# Стек
nvcc stack.cu -o stack

# Очередь
nvcc queue.cu -o queue
```

### Запуск
```bash
./stack
./queue
```

## Контрольные вопросы
1. **В чём отличие стека и очереди?**
   - Стек работает по принципу LIFO (Last In, First Out), очередь — FIFO (First In, First Out).
2. **Какие проблемы возникают при параллельном доступе к данным?**
   - Состояние гонки (Race Conditions), когда несколько потоков пытаются записать в одну ячейку одновременно.
3. **Как атомарные операции помогают избежать конфликтов?**
   - Они выполняются как единая неделимая операция, блокируя доступ другим потокам к данной ячейке памяти на время выполнения.
