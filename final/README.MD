# Сравнение стратегий планирования OpenMP

## Описание проекта

Программа демонстрирует разницу между тремя стратегиями планирования OpenMP при работе с алгоритмом, имеющим **неравномерную нагрузку** по итерациям.

**Предмет:** Гетерогенная параллелизация
**Тема:** Сравнение стратегий планирования OpenMP

---

## Теория

### Что такое OpenMP?

OpenMP (Open Multi-Processing) — это API для параллельного программирования на языках C, C++ и Fortran. Он позволяет легко распараллеливать циклы с помощью директив `#pragma omp`.

### Стратегии планирования (Scheduling)

При распараллеливании цикла итерации нужно распределить между потоками. OpenMP предлагает несколько стратегий:

#### 1. `schedule(static)`
```cpp
#pragma omp parallel for schedule(static)
```
- Итерации делятся **поровну** между потоками **до начала** выполнения
- Пример: 100 итераций, 4 потока → поток 0: 0-24, поток 1: 25-49, поток 2: 50-74, поток 3: 75-99
- **Плюсы:** Минимальные накладные расходы
- **Минусы:** При неравномерной нагрузке возникает дисбаланс

#### 2. `schedule(static, chunk_size)`
```cpp
#pragma omp parallel for schedule(static, 100)
```
- Итерации делятся на блоки размера `chunk_size`
- Блоки распределяются **циклически** (round-robin)
- Пример: chunk=100, 4 потока → поток 0: 0-99, 400-499..., поток 1: 100-199, 500-599...
- **Плюсы:** Лучшая балансировка при неравномерной нагрузке
- **Минусы:** Всё ещё статическое распределение

#### 3. `schedule(dynamic, chunk_size)`
```cpp
#pragma omp parallel for schedule(dynamic, 100)
```
- Итерации распределяются **во время выполнения**
- Когда поток заканчивает блок, он запрашивает следующий
- **Плюсы:** Отличная балансировка при сильно неравномерной нагрузке
- **Минусы:** Накладные расходы на синхронизацию

#### 4. `schedule(guided, chunk_size)`
```cpp
#pragma omp parallel for schedule(guided, 100)
```
- **Комбинация** static и dynamic
- Размер блока **уменьшается** со временем
- Формула: `размер_блока = оставшиеся_итерации / число_потоков`
- **Плюсы:** Хороший баланс между накладными расходами и балансировкой
- **Минусы:** Не всегда оптимален для экстремальных случаев

### Когда какую стратегию использовать?

| Тип нагрузки | Рекомендуемая стратегия |
|--------------|------------------------|
| Равномерная (все итерации одинаковые) | `schedule(static)` |
| Слегка неравномерная | `schedule(static, chunk)` |
| Сильно неравномерная | `schedule(dynamic)` |
| Неизвестная/смешанная | `schedule(guided)` |

## Алгоритм программы

Для демонстрации используется **проверка чисел на простоту** — алгоритм с неравномерной нагрузкой:

- Для малых чисел (n=100) нужно проверить ~5 делителей
- Для больших чисел (n=10,000,000) нужно проверить ~1500 делителей
- Сложность: O(√n)

Массив заполняется числами от 2 до 10,000,000 с линейным распределением, что создаёт ситуацию, где:
- Первые итерации — быстрые (малые числа)
- Последние итерации — медленные (большие числа)

## Результаты тестирования

**Конфигурация:**
- Потоков: 4
- Размер массива: 50,000 элементов
- Диапазон чисел: 2 - 10,000,000
- Размер блока (chunk): 100

**Результаты:**

| Метод | Время (мс) | Ускорение |
|-------|-----------|-----------|
| Sequential | 20.62 | 1.00x (базовый) |
| static | 14.08 | 1.46x |
| static, chunk | 6.38 | 3.23x |
| **dynamic** | **5.43** | **3.80x** |
| guided | 9.42 | 2.19x |

**Лучший метод для данной задачи:** `schedule(dynamic)` с ускорением 3.80x

### Анализ результатов

1. **static (1.46x)** — худший результат среди параллельных версий, потому что последний поток получает самые большие числа и работает дольше остальных.

2. **static, chunk (3.23x)** — значительно лучше благодаря циклическому распределению блоков.

3. **dynamic (3.80x)** — лучший результат! Потоки динамически берут новые блоки по мере освобождения.

4. **guided (2.19x)** — хуже dynamic, потому что в начале выдаёт слишком большие блоки.

## Выводы

1. При **неравномерной нагрузке** статическое планирование (`static`) неэффективно из-за дисбаланса между потоками.

2. **Динамическое планирование** (`dynamic`) показывает лучшие результаты для задач с сильно варьирующимся временем выполнения итераций.

3. **Управляемое планирование** (`guided`) — хороший универсальный выбор, если характер нагрузки неизвестен.

4. Выбор стратегии планирования может значительно влиять на производительность — разница между `static` и `dynamic` составила **2.6x** (14.08 мс vs 5.43 мс).
